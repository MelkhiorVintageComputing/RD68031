# Making it smaller, and making it faster

Each row is a before-and-after on the same tree with one change, from `make impl`
(Artix-7) and `make quartus` (Cyclone V).

| change | kept | what it was worth |
|---|:--:|---|
| M15's starting point: the MC68030 as M14 left it, `COPROCESSOR = 0`, both caches at 64 | -- | Artix-7 **14,835 LUTs**, 5,185 FFs, 6 RAMB36, 4 DSP, **20.87 MHz**; Cyclone V **13,808 ALMs**, 9,827 registers, 22 M10K, 12 DSP, **21.51 MHz**; MAX 10 **34,286 LEs**, 28 M9K, **16.97 MHz**. RD68021 at the same constraint: 8,216 LUTs, 33.68 MHz (`doc/implementation.md`) |
| `COPROCESSOR = 1` | measurement | Artix-7 14,738 LUTs, 21.12 MHz: no difference beyond the router's |
| both caches built out, `ICACHE_ENTRIES = 0`, `DCACHE_ENTRIES = 0` | measurement | Artix-7 11,740 LUTs (−3,095), 3,907 FFs (−1,278), no LUTRAM, **22.84 MHz** (+2.0): the limiting family is unchanged, the ATC's history behind the bus unit's operand continuation |
| the ATC's reset loop indexed by the loop's own variable, not a module-scope `int` | yes | Quartus's `Warning (10240)` latch for the index is gone; no netlist change elsewhere |
| **M15 phase B.** Each row below is `make impl` and `make quartus` (Cyclone V) on the tree of the row above with that one change; "before" is the row above. The phase A tree measured again first, to see the spread: Artix-7 14,856 LUTs, 20.59 MHz (against 20.87) | | |
| S6: the divider's `mag_num` and `mag_den`, written and never read, removed | yes | none in a vendor netlist -- Vivado and Quartus already deleted them (`[Synth 8-6014]`, which is gone); 96 flip-flops fewer in the source and in `make audit`'s yosys netlist, which kept them (6,592 → 6,498 with phase B's two new ones, `crst_nq` and `cdis_sync_n`) |
| S2: both caches' tags read through an unpacked array (`tags[line]`) and the valid bits by a concatenated index (`{line, 2'b00} +: 4`), not `tags[line*TW +: TW]` and `valid_q[line*4 +: 4]` | yes | Cyclone V **13,808 → 12,773 ALMs** (−1,035), **12 → 3 DSP blocks** -- the nine 9×9 multipliers Quartus built for `line*TW` are gone, leaving the multiplier's three -- 9,827 → 9,787 registers, 21.51 → 21.34 MHz (spread). Artix-7 14,835 → 14,856 LUTs, 20.87 → 20.59 MHz: no change, as expected. All six front-ends accept the unpacked net array assigned from a generate (`make lint`, `synth`, `lint-quartus`, `lint-questa`) |
| F2: the residual address `op_addr + xfer_done` as a carry-select -- the three low bits added late, their carry choosing `op_addr[31:3]` or that plus one, both from registers -- with the long-word and page comparisons taken the same way, the burst beat's operand test split into a registered and a late half, and CBREQ's line test on four bits instead of a 32-bit add and compare | yes | Artix-7 **20.59 → 22.23 MHz** (48.56 → 44.98 ns), 14,856 → 14,899 LUTs; Cyclone V **21.34 → 24.47 MHz**, 12,773 → 12,814 ALMs. The limiting family is unchanged, `beat_q`/`st_n` through the ATC into its history bits |
| F1 as first written: the continuing operand's next cycle never looked up at the end of S5; a cycle entering a new page waits an idle clock and is looked up from the operand's registers | (superseded by the row below) | Artix-7 22.23 → 22.25 MHz, Cyclone V 24.47 → 23.48: **nothing**. The lookup's address still waited for the operand engine, through the choice of which requester is next: the sequencer drops `req_valid` on `req_last`, so the ATC looked up the request or the prefetch according to whether the operand was finishing |
| F1 completed: the lookup's requester chosen without the late terms -- the sequencer's request without `req_last` (`req_want`) and not while its own operand is under way, the walker's without `tw_last` (`tw_want`), the MMUDIS the MMU sees chosen from registers, CDIS taken once more on a rising edge, and the lookup's source chosen by the rising-edge bus state alone | yes | Artix-7 **22.23 → 29.66 MHz** (44.98 → 33.71 ns), 14,899 → 14,884 LUTs; Cyclone V **24.47 → 32.80 MHz**, 12,814 → 13,158 ALMs, 9,947 registers. Step by step on the Artix-7: `req_want` and MMUDIS 22.45 MHz, `tw_want` 26.66 (the limit moved to CDIS's synchroniser), CDIS 27.15, the rising-edge choice 29.66. The limit is now a full-period path, the microcode store through the effective address, the data cache's lookup and the ATC. One clock on a misaligned operand across a page boundary with translation enabled (`doc/timing-divergences.md`) |
| F4: the bus unit's falling-edge registers reset from a falling-edge copy of `crst_q` | yes | the `crst_q` family, 36.28 ns at phase A (`make paths`), is not among the 3,000 worst paths after it (the 3,000th needs 23.2 ns). Artix-7 29.66 → 29.50 MHz, 14,884 → 14,867 LUTs, +1 FF; Cyclone V 32.80 → 30.92 MHz, 13,158 → 13,145 ALMs -- both the fitter's spread: neither limiting path goes near the reset |
| S1: one ATC lookup, the bus unit's, shared with the walker on its two clocks that read it (W_FIN, W_PT0), chosen by the walker's state | yes | Artix-7 **14,867 → 14,327 LUTs** (−540; `u_xl3` was 498), 29.50 → 29.61 MHz; Cyclone V **13,145 → 12,884 ALMs** (−261), 9,932 → 9,681 registers, 30.92 → 31.82 MHz. The critical path does not go through the walker's choice |
| M15 phase B, all of it: S2, S6, F2, F1, F4, S1 | -- | Artix-7 **14,327 LUTs, 5,188 FFs, 29.61 MHz** (phase A 14,835, 5,185, 20.87: −3 %, **+42 %**); Cyclone V **12,884 ALMs, 9,681 registers, 3 DSP, 31.82 MHz** (13,808, 9,827, 12, 21.51: −7 %, **+48 %**); MAX 10 **30,361 LEs, 9,300 registers, 28 M9K, 25.71 MHz** (34,286, 9,298, 16.97: −11 %, **+52 %**), limited by the full-period path from the microcode store through the lookups into the ATC's history. Both limited by the same family: from the falling-edge bus state, an operand finishing, the sequencer's next request taken on that edge, into the data cache's RAM write and the ATC's history (`doc/critical-path.md`) |
